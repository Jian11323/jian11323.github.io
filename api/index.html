Jian Project WebSocket 数据服务

WebSocket 推送 UTF-8 JSON 心跳约 30s

多源地震预警、情报与测站数据的实时推送服务，适合学习与对接调试。

基础地址：wss://api.sismotide.top

连接方式：wss://api.sismotide.top/[路径]，例如 wss://api.sismotide.top/cenc

鉴权：公开业务路径与 /all 始终需要访问令牌（邮箱自助：auth.sismotide.top）。握手可带；未带则连上后 15 秒内发送，超时或令牌错误即断开。同一 IP 累计未鉴权掐断 10 次会递增临时封禁（1h 起、封顶 24h）。测站路径无需令牌。详见 连接鉴权。连接数与频率另受 连接限制 约束。

编码：UTF-8 JSON 文本帧

客户端通知：HTTPS 拉取见 通知中心（与 WebSocket 无关，无鉴权）。

通用约定

  • 连接成功后，多数路径会先推送当前最新一条（如有），之后仅在内容变化时更新。
  • 业务帧常见结构为 type + Data + md5（部分源有特例，见对应章节）。
  • 时间默认按北京时间（UTC+8）理解；JMA 等路径的原生时区见各章节说明。
  • 无效路径会立即关闭连接；客户端需自行实现断线重连。
  • 并发与频率限制见 连接限制。

连接限制

为保障服务稳定，公开 WebSocket（含预警/情报与实时测站）按客户端 IP 限连与限频。并发超限时仅拒绝超出的新连接，未超限的已有连接继续保留；频率滥用或管理员封禁则可能临时封禁该 IP。

并发连接上限

按服务类别分别统计限额，预警/情报与实时测站相互独立；同一 IP 在各类别内分别计数，互不占用对方额度。

类别 计入路径（示例） 默认上限
预警 + 情报 /all、/cenc、/cea、/usgs、/jma、/cwa 等公开预警/情报路径 6 条并发
实时测站 /kmoni、/s-net、/kma-station 等公开测站路径 7 条并发
  • 超出对应类别上限时：拒绝新连接；已建立且未超限的连接不受影响。
  • 被拒的新连接会收到错误帧，约 5 秒后断开：
连接数超限
{
  "type": "error",
  "message": "您已超过服务器连接限制"
}
  • 站内融合通道（若已开通）不计入上述并发，不占用公开路径的连接额度。

IP 封禁

IP 被列入黑名单（含频率超限触发的自动临时封禁、或管理员手动封禁）后，新连接与已有连接均会收到错误帧，并在约 5 秒内断开：

IP 已封禁
{
  "type": "error",
  "message": "您的IP已被封禁，请联系管理员进行处理"
}
  • 同一 IP 在短时间窗口内反复建立连接，超过服务端配置的次数上限时，会自动临时封禁。
  • 需鉴权路径未鉴权/令牌错误被掐断累计 10 次，也会自动临时封禁（1 小时起依次递增，封顶 24 小时），详见 连接鉴权。
  • 频率类自动封禁时长由服务端配置；未鉴权类见上。到期后可重新连接。

对接建议

  • 每个业务场景尽量复用长连接，避免频繁断开重连。
  • 预警/情报合计勿超过 6 路（例如 /all + 烈度速报）；公开测站合计勿超过 7 路。
  • 收到 type: "error" 后应停止瞬时重连，按退避策略稍后再试。
  • 断线后建议指数退避重连，勿瞬时打满并发与频率窗口。
  • 更多说明见 服务条款 与 隐私政策。

连接鉴权

公开业务 WebSocket 与 /all 始终需要访问令牌。个人用 QQ 邮箱自助申请登录密钥，软件侧按固定流程换取长期 Token 与短期访问令牌。握手可带访问令牌；未带则连上后 15 秒内发送纯文本 at_…。超时未发送或令牌错误会立即断开，期间不推业务数据。

未鉴权掐断与自动封禁

需鉴权路径在未携带合法访问令牌（含 15 秒内未补发）、或令牌格式/内容错误时，服务端回错误帧后立即掐断，不推送任何业务数据。同一公网 IP 累计被上述方式掐断 10 次后，自动临时封禁该 IP：

  • 首次触发：封禁 1 小时；
  • 再次达到 10 次：封禁 2 小时，之后按小时依次递增（3、4…）；
  • 单次封禁时长封顶 24 小时；
  • 封禁期内新连接与已有连接会收到 IP 已封禁错误帧（见 连接限制）；到期后可再连，但若继续无鉴权狂连会再次累计并更长封禁；
  • 令牌并发超限（conn_limit）与账号封禁（account_banned）不计入上述 10 次。

步骤 1 · 获取登录密钥

打开 https://auth.sismotide.top/，填写 QQ 邮箱（@qq.com / @foxmail.com / @vip.qq.com），勾选个人信息处理说明后提交。登录密钥仅出现在邮件正文，约 5 分钟内有效，使用一次即失效。

  • 每邮箱最多同时保留 5 把未过期的长期 Token；默认换票为追加，已满 5 把时会自动作废最早的一把。
  • 需要一次性作废该邮箱全部旧票并签发新票时，请勾选「吊销全部旧 Token 后签发」再申请。
  • 仅注销、不要新票时，在申请页点「注销本邮箱所有长期 Token」，按邮件内确认链接（5 分钟内）完成；确认后该邮箱下全部长期 Token 与访问令牌失效。
  • 同一邮箱有发送冷却（约 60 秒）；请勿短时间反复点发送。
  • 同一网络地址每个自然日（北京时间）最多发送 5 封登录密钥（注销确认邮件计入同一限额）。该地址当天只认第一次填写的邮箱；换用其他邮箱也会直接拒绝，不再发信。

常见错误

换票接口与 WebSocket 握手失败时返回 JSON：{"ok":false,"error":"…","code":4003,"message":"…"}。error 为稳定字符串；code 为本站自有数字错误码（四位正数，与第三方体系无关）。

code error 含义与处理

4003 invalid_api_key 访问令牌无效（未登记或已吊销）；重新换取 at_…

过期时间从哪里看

服务端不会在 WebSocket 里推送剩余时间。登录密钥的 5 分钟写在邮件正文。长期 Token 和访问令牌的时长只出现在换票 JSON 里，从收到该次响应的时刻起算：

  • 登录密钥 lk_…：邮件写明 5 分钟，用过即失效。
  • 长期 Token rt_…：/api/refresh 与 /api/access 均返回 refresh_expires_at（Unix 秒）与 refresh_expires_after_min；签发时另有兼容字段 expires_after_min（259200 分钟，即 180 天）。
  • 访问令牌 at_…：GET/POST /api/access 的 expires_after_sec（3600 秒，约 1 小时）。记下拿到响应的时间，加上该秒数，就是这次访问令牌的失效时刻。

过期与断线

访问令牌过期后，服务端不会自动换发新的 at_…，也不会在已有连接上推送新令牌。长期 Token 同样不会自动延长。

  • 握手可带访问令牌；没带则连上后 15 秒内再发一次。通过之后，at_… 过期不会因此被断开。心跳只维持链路，不延长访问令牌，也不当作令牌。
  • 若访问令牌已经过期，此时 WebSocket 又断开：不要用旧的 at_… 重连，会被拒绝。须先用未过期的 rt_… 调用 GET/POST /api/access 取得新的访问令牌，再连接。
  • 连接尚未断开时也可以提前换票（例如剩余不足 5 分钟，或每次准备重连之前）。新的 at_… 不会拆掉当前连接。
  • rt_… 过期或丢失后，须重新申请登录密钥，再换长期 Token。只保存 at_…、不保存 rt_… 时，过期后无法自行恢复连接。

对接建议

  • 长期保存 rt_…。at_… 只用于当次连接（握手或连上后 15 秒内），进程启动、临近过期或断线重连前再调 /api/access。
  • 通过之后不要再发令牌。未在握手携带时，只在连上后 15 秒内发一次纯文本 at_… 或 {"key":"at_…"}，不要使用 type:"auth"，也不要写进业务帧。
  • 令牌并发上限（默认 3）与 IP 连接限制同时生效，取更严的一侧。
  • 收到 missing_api_key / 令牌错误后应停止瞬时无钥重连；累计 10 次无鉴权掐断会触发递增 IP 封禁（见上文「未鉴权掐断与自动封禁」）。
  • 禁止把登录密钥、长期 Token、访问令牌写入公开仓库或截图外传。若怀疑泄露，请立即在申请页自助注销全部长期 Token。
  • 服务端会在每把长期 Token 首次成功换取访问令牌时记录调用 IP 与可选请求头 X-Jian-Client-Fp；之后若环境相对首次记录变化，可能向该邮箱发送安全提醒（不阻断换票）。日常换票成功不会发邮件。家用宽带更换公网 IP 也可能触发提醒，请结合是否本人使用判断。

心跳与保活

连接建立后，服务端向客户端约每 30 秒下发一帧心跳，用于保持链路活跃、探测断线。心跳帧与业务帧结构不同，可按 type 区分并忽略。

服务器 → 客户端 · heartbeat

heartbeat

  "type": "heartbeat",
  "ver": "2.0.0",
  "id": "550e8400e29b41d4a716446655440000",
